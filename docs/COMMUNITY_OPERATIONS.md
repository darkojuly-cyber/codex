# 社区配置、人员授权与运营概览

## 更新与启用

本次更新包含保持登录、工单和运营后台增量，可一次下载更新。先 `Stop.cmd`，将新文件放在项目根目录，保留 `.env.local`、`.env` 和 `.data`，再 `Start.cmd`。启动时自动迁移数据库并构建变化的源码；没有新增 npm 依赖或 Discord 指令，不需要再次注册命令。

正常使用需要 Bot、API、Worker 持续运行，Caddy 提供本机 HTTPS。Bot 关闭期间不会补采历史事件。保持登录沿用 30 天持久会话。

## 一个配置入口

原「运营阶段」合并到「设置」，在同一页面编辑阶段、链接、功能开关、频道绑定和工单限额。所有字段属于同一份配置草稿，跨页面切换保留未保存内容。

流程为：编辑 → 保存配置草稿 → 点击页面上方「审核与发布」→ 查看所选版本 → 发布。保存不会立即生效；历史记录放在弹窗中，避免占据整个页面。查看版本不会覆盖当前编辑内容。积分规则仍在「积分与奖励」独立审批，不随通用配置发布。

## 昵称显示

工单申请人/处理人/备注作者/回复作者、积分成员/流水操作人/规则作者和审核人、排行榜、配置作者、审计操作人及人员授权优先显示服务器昵称，再使用 Discord 全局显示名或用户名，同时保留 ID。昵称为最近观察或查询到的当前名称，不是事件发生时的名称快照。离群或 Discord 查询暂时不可用时，使用已观察名称；没有可靠名称就显示 ID，不编造人员。

可见人员批量解析，缓存 Discord 查询，避免每条记录分别验证后台登录。身份和授权仍以 ID 为准，输入授权或分配目标时不会凭昵称猜测账号。

## 超级管理员授权

「设置 → 工作人员授权」只对超级管理员开放。填写目标成员 ID、选择权限角色、填写理由，保存后立即撤销该成员旧的后台会话；下次登录按新权限验证。目标必须仍属于当前服务器。个人授权覆盖部署角色的继承权限；勾选「撤销后台访问权限」可以阻止继承角色继续登录。

| 角色 | 可执行操作 |
| --- | --- |
| 超级管理员 | 所有后台操作、工作人员授权、公开频道关键词采集配置 |
| 社区经理 | 通用配置编辑/发布、消息、积分管理、全部工单、运营数据、风险审核、审计 |
| Moderator | 全部工单、运营数据、风险审核、审计；不能发布配置、发公告或调整积分 |
| Support | 仅本人创建/分配给自己的工单；不能查看全服运营数据、风险线索、积分管理或配置 |

超级管理员白名单 `SUPER_ADMIN_USER_IDS` 保留在部署配置，后台不能增加超级管理员或修改受保护账号，避免管理员被误撤权。每次请求仍验证服务器成员身份，退出服务器的账号不能凭旧会话继续使用。

人员授权会排队刷新工单频道权限：经理/Mod 可访问全部工单；Support 仅获得本人/分配工单的权限；撤权、降级或转交将移除对应授权。待同步期间回复队列暂停，后台显示同步状态。Discord 服务器所有者和原生 Administrator 权限可以绕过频道覆盖，后台授权不会修改这些原生角色。积分资格沿用原规则：Admin/Mod 都保留积分，只有 Discord Admin 不参与排行榜；后台人员授权不会自动改变积分资格。

## 概览指标

概览提供 1、7、30 个自然日范围，使用通用配置中的时区；范围包含当天，因此当天数据未完整。显示开始采集时间、最近状态、Bot 在线/离线和缺失提示，每 30 秒刷新。

| 指标 | 口径 |
| --- | --- |
| 入群人数 | 收到的非机器人入群事件数，同一成员重新加入再次计数；重复投递去重 |
| 离群人数 | 收到的非机器人离群事件数，重复离开通知不会重复计数 |
| 净增长 | 同一时段的入群数减离群数，并非当前成员总量快照 |
| 发言数量 | 收到的新消息条数，排除机器人、Webhook、系统消息、私密频道、私密线程和工单；附件消息也计一条 |
| 发言人数 | 所选整个时段内发送上述消息的成员去重数；不是每日人数相加 |
| 每日明细/趋势 | 按同一配置时区汇总每天的入离群、消息和发言人数；只展示已观察事件的日期 |
| 本周积分榜 | 使用已发布积分规则时区的自然周，包含积分更正，同分同名次，管理员排除；与 Discord 榜单同源 |

入离群需要 `GUILD_MEMBERS_INTENT=true`，同时在 Discord Developer Portal 开启 Server Members Intent。公开消息数量使用 Guild Messages Intent，Bot 自动请求；只统计数量不要求 Message Content Intent。关键词提示和现有聊天积分需要 `MESSAGE_CONTENT_INTENT=true` 以及 Developer Portal 对应开关。

这些记录从新版本 Bot 运行后开始，不扫描旧聊天或历史成员；关机、网络中断、未启用相应 Intent 都会造成缺口。`—` 表示未接入对应采集，不代表零。入离群与消息仅保存事件元数据，不保存聊天正文，事件元数据保留 90 天，Bot 启动时清理超期数据。此版本没有估算或伪造停机期间数据。

## 舆情风险线索

按本次确认采用公开频道关键词提示与人工审核，不做情绪百分比分数、不自动处罚。由超级管理员在「概览 → 社区风险审核 → 配置关键词提示」显式选择公开频道 ID、排除的分类 ID 和关键词（每行一个），再启用采集。没有填入有效范围和关键词时不能启用。

只有新消息在指定公开频道命中关键词时才记录线索；可选择公开论坛/线程的父频道。工作人员私密频道、私密线程和工单始终排除。只保存匹配到的关键词、作者 ID、消息/频道 ID 和时间，原文在 Discord 中查看；不保存正文、下载附件、扫描历史或回扫消息编辑。

管理员、经理和 Mod 可打开线索列表，查看原消息，填写审核理由后标记「排除误报」或「确认需要跟进」。审核有操作者及审计记录，同一线索不能重复覆盖审核；后续沟通/处理仍由工作人员判断。命中不是确认违规；未启用采集、权限不可用或 Bot 离线时，零条线索也不能证明没有风险。

## 验证边界

自动验证使用本地 PGlite、模拟 Discord HTTP 和 Mock 浏览器环境；UI 昵称测试对测试账号提供明确的模拟响应。没有连接用户的 Neon 或真实 Discord，首次本机更新仍需检查昵称解析、成员 Intent、公开频道采集范围和真实权限。云端没有自动改变线上已发布配置、人员授权或关键词设置。
